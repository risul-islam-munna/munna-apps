# Munna Apps — apps.munna.dev

Bilingual (English / বাংলা) static marketing, guide and legal site for **apps.munna.dev**.
The pages are generated by a tiny dependency-free Node script into plain HTML at the
repository root, so the site stays fully static and GitHub Pages can serve the branch as-is.
No backend, no database, no runtime translation, and no web version of any app.

## Routes and language rules

One canonical URL per page; both languages live in the same file. Each area has its own language
scope (`src/routes.mjs` → `SCOPES` / `AREAS`, passed to `page()` in `src/layout.mjs`):

| Page | Canonical URL | Scope (localStorage key) | Default |
|---|---|---|---|
| Hub | `/` | `munnaApps.language` | English |
| Bahon Boi landing | `/bahon-boi/` | `bahonBoi.language` | বাংলা |
| Guide index / topics | `/bahon-boi/guide/`, `/bahon-boi/guide/<topic>/` | `bahonBoi.language` | বাংলা |
| Contact / Terms / Privacy | `/bahon-boi/{contact,terms,privacy}/` | `bahonBoi.language` | বাংলা |
| 404 | `/404.html` (both languages side by side — GitHub Pages serves one 404) | — | — |

- Static HTML holds the **default language** (what crawlers, social previews and no-JS visitors get:
  title, description, OG/Twitter, JSON-LD, canonical). The other language is an inert
  `<template id="lang-alt">`; `assets/lang.js` (loaded at the end of `<body>`, not deferred) swaps it
  in when the visitor's saved choice for that scope differs, and on `বাং | EN` clicks. A tiny inline
  `<head>` script hides `#lang-root` while a non-default saved language is applied (1.5 s CSS fallback).
- Switching never changes the path, `?query` or `#hash`; the section at the top of the view stays in
  place, focus returns to the new language button, `<html lang>`, title, description, OG/Twitter text and
  OG image are updated, and `site.js` re-binds (header fit, menu, scroll spy, animations) on `langchange`.
- Browser language is never used. Blocked/unavailable localStorage: the switch works for the current page
  only; other pages show their defaults. Without JavaScript the switch is hidden and links work normally.
- The scopes are independent: choosing English in Bahon Boi does not change the hub, and vice versa.
  The hub's "Open it in English" link (`data-prefer="bahonBoi:en"`, JS only) saves the Bahon Boi
  preference before opening `/bahon-boi/`.
- Section ids are identical in both languages (the build fails otherwise; SVG `<title>/<desc>` ids exempt).
- **One URL means no separate indexing or shareable link per language** — by design.
- Legacy URLs (`LEGACY` in `src/routes.mjs`) are ~0.7 KB redirect stubs, not content pages: `/bn/` → `/`
  (saves `munnaApps.language=bn`); `/bahon-boi/en/`, `/bahon-boi/en/guide/…`,
  `/bahon-boi/en/{contact,terms,privacy}/` → the same path without `en/` (saves `bahonBoi.language=en`).
  They use `location.replace` keeping `?query` and `#hash`, have `noindex` + canonical, a `<noscript>`
  meta refresh and a plain link; they never redirect to themselves. The build fails on any internal
  link to a legacy path.
- Hub = portfolio introduction (apps + games), not a Bahon Boi page. Hero (2026-11-11): headline
  "Simpler everyday tasks. More enjoyable downtime." / "দৈনন্দিন কাজ হোক সহজ। অবসর হোক আনন্দের।",
  *Explore apps* (`#apps`) and *Explore games* (`GAMES_URL` = `https://games.munna.dev`), then one stage
  (`.hx-stage`) with two original inline-SVG scenes and HTML captions: **apps** — loose notes settle into a
  tidy checked list with a progress bar (illustrative, no data); **games** — a ball knocks out one brick
  (small sparkle), a puzzle piece snaps in, the paddle slides under the ball. The games caption links to
  games.munna.dev; the separate "I make games too" banner was removed (it repeated the hero).
  Animation: CSS only, ~3.6 s once (`.hx-anim`), transforms/opacity, no loops; the static final state is
  the default (reduced motion, no animation support, and after a language switch — `site.js` drops
  `.hx-anim`). A replay button (JS only, hidden with reduced motion) restarts it. "With friends" copy is
  limited to "some games" (verified: Dual Play pass-and-play / paired devices in supported games).
  Then the featured Bahon Boi panel (screenshots), developer, contact. Games content stays on
  games.munna.dev — no catalog here. Only add an app card for an app with a verified name, icon,
  destination and status.
- Bahon Boi app (`lib/app/site_links.dart`) opens the canonical `/bahon-boi/…` URLs for both app languages;
  the app language is not passed to the browser.

## Project structure

```
build.mjs                 generator + checks (--release / --check) + asset versioning
src/
  lib.mjs                 L(en, bn) bilingual strings, money/digit formatting, checks
  routes.mjs              canonical routes, language scopes/defaults, legacy redirects
  layout.mjs              <head>, header with language switch, footer, both-language page, redirect stubs
  components.mjs          icons, example cards, breadcrumbs, link pills
  svg.mjs                 original inline SVG illustrations (theme-aware, translated labels)
  examples.mjs            accounting examples — computed and asserted at build time
  content/guide.mjs       the 11 guide topics (EN + BN)
  pages/hub.mjs  app.mjs  guide.mjs  legal.mjs   (legal.mjs also has contact + 404)
assets/                   site.css (design system), lang.js (language switch), site.js (optional enhancements), hub icons, OG covers
bahon-boi/assets/         app icon sizes, favicon, logo-320.webp, OG covers (bn default, -en)
docs/FEATURE_COVERAGE.md  feature → page → app-source checklist (internal)
app-config/               hand-edited update config the apps fetch (validated by the build) — see app-config/README.md
bahon-boi/assets/screens/ genuine app screenshots (<lang>-<screen>.webp, 640×1314)
*.html, bn/, bahon-boi/   GENERATED — do not edit by hand
CNAME .nojekyll robots.txt site.webmanifest sitemap.xml (generated)
```

## Local preview (Laravel Herd)

`~/Herd` is a parked Herd path, so the site is served at **http://munna-apps.test/** with no setup.
Commands (Herd's Node works: `~/Library/Application Support/Herd/config/nvm/…`):

```sh
cd /Users/munna/Herd/munna-apps
node build.mjs              # while editing: regenerate with the current release id
node build.mjs --check      # read-only validation (never writes, never mints an id)
node build.mjs --release    # RELEASE: new release id + build + all checks — run before every publishing commit
```

Herd quirks (production behaves correctly): unknown paths fall back to the home page instead of
`404.html`, and macOS file names are case-insensitive. For production-like behaviour use
`python3 -m http.server 8766` and open `http://localhost:8766/`.

`--check` fails when the committed output is stale (sources changed but not rebuilt), when versioned
CSS/JS changed since the recorded release (`assets/release.json`) — i.e. `--release` was skipped — on
unversioned/stale asset URLs, broken internal links/assets, missing `#anchors`, duplicate ids (per language),
section ids that differ between languages, links to legacy language URLs, `hreflang`, or stray HTML,
and warns about English text in the Bengali version or Bengali text in the English version of a page.

## Editing content

- All copy goes through `L('English', 'বাংলা')`; the build stops if either side is missing.
- Feature copy must match the released app. Verify against the app's bundled guide
  (`lib/features/guide/guide_content.dart`), translations and `PROJECT_REPORT.md` §2/§8, and update
  `docs/FEATURE_COVERAGE.md`. Use the app's exact button names. Never advertise planned features.
- Accounting examples live in `src/examples.mjs`; values are computed and checked, so a wrong
  example fails the build. Label every figure as an example.
- Keep earned income, money received, dues, expenses, payments, profit, cash movement and non-cash
  adjustments separate in all copy.

### Legal pages (drafts)

Terms and Privacy show a draft banner and `TODO` markers, use `noindex`, and are left out of the
sitemap. To publish: resolve every `TODO` (`grep -rn TODO src/pages/legal.mjs`), confirm the
permission list from the release build's merged Android manifest, set the effective date, remove the
`draft-banner`, set `robots` to index in `legalPage()`, mark those routes indexable in `build.mjs`,
and rebuild.

## Images

- App icons are resized from the app's `assets/images/branding/bahon_boi_logo.png` (ImageMagick:
  `magick SRC -strip -resize 512x512 -colors 64 icon-512.png`; WebP via `cwebp -q 88 -resize 320 320`).
- Illustrations are original inline SVG in `src/svg.mjs`, coloured by CSS classes so they follow
  light/dark mode. Text labels are translated; each SVG has `<title>`/`<desc>` in the page language.
- Screenshots in `bahon-boi/assets/screens/` are genuine captures of the current app on the Pixel_9_Pro
  emulator in **normal mode (demo mode off)**, filled with fictional records by the app repo's
  development-only fixture `tool/screenshots/fixture_main.dart` (seeds through the app's own
  repositories; refuses to touch a database that already has records). Status and gesture bars are
  cropped; nothing inside the app is edited. Export: `magick X.png -crop 1280x2628+0+156 +repage
  -resize 640x Y.png && cwebp -q 80 -m 6 Y.png -o <lang>-<screen>.webp`. Shown together in the
  hero and the “Inside the app” section (no carousel); alt text and captions live in
  `SCREENS` in `src/components.mjs`.
- OG covers (1200×630) were rendered from small HTML templates with headless Chrome. The hub covers
  (`assets/og-cover.png`, `-bn`) were regenerated on 2026-11-10 with the Munna Apps mark and the apps + games
  headline.

## Header and navigation

- One row: brand · navigation · `বাং | EN` + menu button. `assets/site.js` measures whether the row
  fits (in the current language and fonts; re-measured after a language switch) and switches to the menu button before anything
  wraps; measured collapse points: hub ≈ 630–640 px (with the external *Games ↗* link), Bahon Boi ≈ 690 px (en) / 730 px (bn). Without
  JavaScript the nav wraps under the brand instead. The menu supports Escape, focus return and
  `aria-expanded`/`aria-controls`.
- The hub's *Games* nav link is external (`https://games.munna.dev`), so the scroll tracker ignores it.
  Games links appear in the hub header/footer only; Bahon Boi pages' header and footer are unchanged.
- In-page links (`#features`, `#faq`, hub sections) get `aria-current="location"` from a scroll
  tracker: the section under a line just below the sticky header is active; at the page bottom the
  last visible linked section wins; none in the hero. Links to other pages (guide, contact) get
  `aria-current="page"` only on that page. `--header-h` drives `scroll-padding-top`.

## Adding another app

1. Add routes in `src/routes.mjs` (one canonical `/<slug>/…`), plus a scope in `SCOPES` and an area in
   `AREAS` (its own storage key and default language).
2. Create `src/pages/<slug>.mjs` (+ its own legal/contact text — never reuse another app's policy).
3. Register the pages in `build.mjs`, add assets under `/<slug>/assets/`, a card on the hub, and
   an accent class in `site.css`.
4. `node build.mjs --release` (or `node build.mjs --check` to validate without writing).

## Releasing and caching

**Release command** (GitHub Pages serves the committed files as-is — nothing builds on GitHub, so the
build must run before the commit):

```sh
node build.mjs --release && git add -A && git commit -m "Release …"   # then push (when authorized)
```

**Asset versioning.** `/assets/site.css`, `/assets/site.js` and `/assets/lang.js` are referenced as
`…?v=<release id>` on every generated page (404 included), keeping any existing query/#fragment. The id is
minted once per `--release` run: `RELEASE_ID` from the environment if a deployment provides one, else the
build's UTC timestamp (e.g. `20261110T202221Z`; a second release in the same second gets a suffix). It is
stored with the assets' SHA-256 prefixes in `assets/release.json`; plain builds and `--check` reuse it, so
validation never changes files. The id changes when the **release build runs**, not when `git push` runs —
pushing output built with an old id keeps the old asset URLs (and `--check` fails if CSS/JS changed). The
scripts import nothing else; fonts are external; images keep their own paths. No service worker exists.

**Why this was needed (diagnosed 2026-11-10).** After the second push, production HTML and `lang.js` were
new (Last-Modified 20:15) but Cloudflare's edge still answered `/assets/site.css` and `site.js` from cache
(`cf-cache-status: HIT`, Last-Modified 14:20 = first release) while GitHub's origin already had the new
files. GitHub Pages sends `Cache-Control: max-age=14400` for CSS/JS, so the edge and browsers may keep an
unversioned asset for up to 4 h. New HTML + old `site.css` (no styles for the button language switch or the
hero) = the broken layout. Versioned URLs make each release fetch its own copy.

**HTML cache limit.** HTML must be current for new asset URLs to be seen. GitHub Pages sends
`Cache-Control: max-age=600` for HTML (not configurable on Pages; `_headers` files and `<meta>` tags do not
change CDN caching), so a browser can show the previous release's page for up to ~10 minutes. Cloudflare
currently does not cache the HTML (`cf-cache-status: DYNAMIC`) — keep it that way.

**Cloudflare settings (recommended; not changed by this repo — needs dashboard access):**
- Caching → Configuration → *Caching level: Standard* (query string is part of the cache key — verified:
  `?v=test1` was MISS, then HIT). Do **not** use *Ignore Query String*, and do not add a Cache Rule that
  ignores the query string for `/assets/*`.
- Do **not** add a *Cache Everything* rule for HTML with a long Edge TTL. If HTML caching is ever wanted,
  use a short Edge TTL and purge the changed HTML URLs (not the whole zone) after each release.
- Optional: a Cache Rule for `apps.munna.dev/assets/*.css|*.js` with a long Edge/Browser TTL is safe now
  that URLs are versioned.
- Scrape Shield → *Email Address Obfuscation*: it currently rewrites `mailto:` links and injects
  `email-decode.min.js`; its decoder misses the inactive-language `<template>`, so after a language switch the
  address showed as "[email protected]". The generated regions are wrapped in `<!--email_off-->`, which
  Cloudflare honours; turning the feature off is the simpler alternative (also helps no-JS visitors).
- After this change is first deployed, purge `/assets/site.css`, `/assets/site.js`, `/assets/lang.js` (the
  old unversioned URLs) once, for anyone still loading an old cached page. Never purge on every visit.

## Deployment

Same model as games.munna.dev: GitHub Pages → *Deploy from a branch* → `main`, `/ (root)`;
`CNAME` (`apps.munna.dev`) and `.nojekyll` are present. Cloudflare DNS: `CNAME apps →
<github-user>.github.io`, DNS-only until GitHub issues the certificate, then *Enforce HTTPS*
(and *Full (strict)* if proxied). Always run `node build.mjs --release` and commit the generated HTML
before pushing. Then submit `https://apps.munna.dev/sitemap.xml` in Search Console.
